# Git Auto Commit

Gitリポジトリの変更を確認し、コミットメッセージを提案し、ユーザーの承認を得ながら
`git add` → `git commit` → （任意で）`git push` まで進める半自動フロー。

## 前提条件

- カレントディレクトリがGitリポジトリであること
- `git` コマンドが利用可能であること
- コミット権限があること

これらが満たされない場合は、実行前にユーザーへ状況を報告し、次の指示を確認すること。

## 絶対に守ること（禁止事項）

- ユーザーの承認なしに `git add` を実行しない
- ユーザーの承認なしに `git commit` を実行しない
- ユーザーの承認なしに `git push` を実行しない
- `--force` / `-f` を使用しない
- `git reset --hard` や `git clean -fd` など破壊的な操作を提案・実行しない
- 各ステップの終了後は、次のステップに進む前に必ずユーザーの応答を待つこと。自己判断で連続実行しない

## 手順

以下のステップを**必ず順番に**実行し、各ステップの終わりでユーザーの確認を待つこと。

### Step 1: 現在の状態確認

実行:

```bash
git status
```

必要に応じて追加で確認:

```bash
git diff --stat
git diff
```

変更内容（変更・追加・削除されたファイル）を要約してユーザーへ報告する。

その後、次のように質問し、ユーザーの返答を待つ:

> この内容でコミット対象を確認しました。次にコミットメッセージを作成しますか？

### Step 2: コミットメッセージ作成

変更内容を解析し、[Conventional Commits](https://www.conventionalcommits.org/) 形式を優先して
コミットメッセージ候補を3つ作成する。

例:

```
feat: add login validation
fix: resolve null pointer in user service
docs: update installation guide
```

ユーザーに番号で選んでもらうか、自由入力してもらう。

選択後、次のように確認する:

> このメッセージでコミットしますか？

ユーザーの承認を待つ。

### Step 3: ステージング

実行前に、どのファイルを追加するかを一覧表示する。

デフォルト候補:

```bash
git add .
```

必要であれば個別ファイル指定（`git add <file1> <file2> ...`）も提案する。

実行前に次のように確認する:

> この内容でステージングしますか？

承認後のみ実行する。

### Step 4: コミット

実行:

```bash
git commit -m "<選択されたメッセージ>"
```

成功・失敗を表示する。

完了後、次のように選択肢を提示し、ユーザーの入力を待つ:

```
コミットが完了しました。

次に行う操作を選んでください。

1. Pushする
2. ログを見る
3. 終了
```

### Step 5: Push（任意）

ユーザーが「Pushする」を選択した場合のみ実施する。

現在のブランチを確認:

```bash
git branch --show-current
```

表示後、次のように確認する:

> origin/<branch> にPushします。実行してよろしいですか？

承認後のみ実行:

```bash
git push origin <branch>
```

Push後は結果を報告する。

## エラー時の対応

コンフリクト・未追跡ファイルの衝突・コミット失敗などが発生した場合は、
自動で解決しようとせず、状況を説明した上でユーザーへ次の操作を確認すること。
